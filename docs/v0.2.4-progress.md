# 0.2.4 文件与文件夹导入修复记录

## 复现与原因

- 用户视频 IMG_2623.MP4：文件夹内的系统取消入口缺失，需要逐层返回；选择文件夹或多个文件后点“打开”未完成导入。
- 直接在内存中审计远端 0.2.3 测试 IPA（产物 ID 12554853051），主程序代码签名没有 entitlements。模拟器配置却包含 application-identifier 和 keychain-access-groups；原生测试通过不能证明真机文件提供程序授权成功。
- 参考 [RepoPocket 文件选择器](https://github.com/wm0104/RepoPocket/blob/main/RepoPocket/WorkspaceDocumentPicker.swift) 的公开 UIViewController containment 和固定取消入口，以及其真机身份签名配置。未使用私有视图层级或系统导航栏修改。
- [TrollStore RootHelper](https://github.com/opa334/TrollStore/blob/main/RootHelper/main.m) 会为没有 entitlements 的主程序填入通配应用身份和钥匙串组；本包改为明确的专属应用身份。签名差异是与视频一致的重要修复依据，用户 iOS 16.3 真机授权结果仍需实测。

## 改动

- 在系统 Files 浏览器外提供固定“取消导入”按钮，进入多层目录后仍可直接退出。
- 每次选择器使用独立 UUID 请求；选择、取消只回调一次，旧请求不会干扰新请求。业务请求身份不再依赖可被 Files 自动清空的弹窗绑定。
- 导入在选中回调内同步消费安全授权；实际 UIKit 关闭与选中结果汇合后再打开项目或编辑器，不依赖固定延时，也不只依赖 SwiftUI onDismiss。全屏覆盖不作为关闭事件。
- 真机应用签名写入 application-identifier `TROLLTROLL.com.wjc0104.pylearn`、团队标识与应用钥匙串组，不请求平台应用或任意文件系统权限。
- 保留旧的专属组与 TrollStore 默认钥匙串组，以便继续读取此前保存的密钥；历史真机钥匙串兼容性尚未实测。
- IPA 检查直接解析主程序的实际代码签名，拒绝缺失或不匹配的应用身份，以及格式错误的钥匙串权限数组，不只检查配置文件。
- 保留原来的整夹递归复制、资源保留、UTF-8 文本限制和 1000 文件 / 50 MiB 上限。导入仍复制到应用本机项目。
