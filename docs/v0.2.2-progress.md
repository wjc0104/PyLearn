# 0.2.2 测试包记录

## 用户视频与原因

- IMG_2608：Git 提交后出现 `[Errno 45] ios does not support processes`。实际为 Dulwich 在更新 HEAD 后执行 post-commit shell hook；`no_verify=True` 不跳过此钩子，因此界面把已经生成的本地提交误报为失败。同步的两个提交编号对应 `DivergedBranches`，必须解释远端领先/分歧并保留两端代码。
- 项目文件长按菜单确实缺少删除。新增文件与文件夹删除，先保存最新内容，再移至仓库之外的恢复副本，移除缓存并修复入口，保存失败则回滚。
- IMG_2611：实际发送模型测试请求后自动关闭选择页，成功文字未能显示。改为先展示测试通过与返回内容，由用户明确确认才启用；失败/取消保留当前模型。
- 参考 wm0104/RepoPocket 当前 main `6b53bee3d1fd7c3d58c1aa9eb65653d4dafe8d25` 的本地/远端结果区分和不强推原则；未迁移 libgit2 内核。

## 验证

- 修复前工作流 40039651347 复现：删除项目文档后磁盘文件仍存在，入口也未修复。禁用 subprocess.Popen 的 Python 测试复现用户相同的 iOS 错误。
- 本地 42 项 Python 回归通过，涵盖禁止子进程的提交/历史/删除同步、重复提交去重、远端拒绝时保留本地提交。
- 真实 GitHub HTTPS 临时分支测试复现另一个错误：默认协议可看到新 SHA，但对应对象未进入本地对象库。拉取改用协议 v0 后，真实传输的新增中文文件、双向修改、删除、提交并推送、拉取全流程通过，临时远端分支已删除。
- Sol 独立审查发现异步测试期间配置可编辑导致成功提示与实际测试配置不符；已在加载/测试期间禁用配置表单。
- 原生编译、内置 Python、真实 HTTPS 克隆和模型确认/失败界面测试待最终工作流验证。
